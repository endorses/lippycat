# v0.11 Production Regression and Lifecycle Fixes

**Date:** 2026-09-02

**Status:** In progress (Phases 1-3 complete)

**Priority:** Release-blocking performance, packet-loss, and data-integrity regressions

## Objective

Remove the confirmed v0.11.x nonlinear packet-processing hot paths, make
per-call PCAP finalization irreversible and race-safe, preserve existing
detection and call-correlation behavior, and add regression and operational
coverage that prevents these failure modes from returning.

## Scope and implementation decisions

- [ ] Treat the RTP lookup regression as the first, surgical fix: no operation
  proportional to active-call count may run on the per-packet hit path.
- [ ] Treat detector batch eviction as the release hotfix: retain bounded maps
  and oldest-first victim selection while adding hysteresis at the cap.
- [ ] Do not introduce per-packet intrusive-LRU writes in this change; exact LRU
  touches could replace the current scan with a new shared-lock bottleneck.
- [ ] Include the adjacent detector synchronization, cleanup, and observability
  work because it affects the safety and diagnosability of the eviction fix.
- [ ] Treat per-call PCAP completion as an explicit lifecycle transition rather
  than the absence of an entry in the live-writer map.
- [ ] Guarantee that an artifact reported as complete is never subsequently
  truncated, appended to, recreated under the same logical name, or reported
  complete a second time because of a late packet.
- [ ] Unify explicit call completion, idle reclamation, and capacity eviction so
  all terminal paths apply the same endpoint cleanup, tombstone, file-close,
  hook, and telemetry policy.
- [ ] Keep public configuration backward compatible. Existing zero-or-negative
  cap behavior must continue to disable cap-based eviction.
- [ ] Treat this plan as a corrective follow-up to the detector caps introduced
  by `docs/plans/concurrency-memory-hardening.md`; do not reopen unrelated work
  already completed by that plan.

## Non-goals

- [ ] Do not redesign the complete detector or call-registry architecture.
- [ ] Do not change detector cap defaults without separate production sizing
  evidence.
- [ ] Do not make cumulative retention control the instantaneous sampling label;
  the UI change only clarifies that they describe different time horizons.
- [ ] Do not treat increasing `perCallReopenWindow` beyond `MaxIdle` as a fix;
  reopening an artifact after its completion hook violates finalization even if
  the operation appends rather than truncates.
- [ ] Do not silently merge late packets into a finalized PCAP. Late-packet
  preservation, if enabled, must use a distinct collision-proof artifact and a
  separately documented lifecycle.
- [ ] Do not claim durable exactly-once hook delivery across process crashes
  unless persistent hook state is explicitly introduced. This scope guarantees
  in-process exactly-once hooks and non-destructive file handling after restart.
- [ ] Do not enforce hardware-specific wall-clock benchmark thresholds in CI;
  use cardinality scaling and allocation behavior for regression automation and
  retain absolute timing as release evidence.

## Phase 1: Establish baselines and acceptance thresholds

- [x] Record current benchmark results for detector insertion at caps of 1,000,
  10,000, and 100,000 entries, including `ns/op`, `allocs/op`, and tail/batch
  latency where the benchmark harness permits it.
- [x] Extend the RTP lookup benchmarks to cover destination hits, source hits,
  and misses with 10, 1,000, and the configured maximum number of active calls.
- [x] Record current RTP benchmark allocation counts separately from runtime so
  endpoint string formatting is not confused with call-slice allocation.
- [x] Preserve representative CPU profiles or benchmark output as review
  artifacts so the before/after claim is reproducible.

## Phase 2: Remove active-call materialization from RTP lookup

- [x] Add cheap, concurrency-safe count accessors to
  `internal/pkg/callregistry.Core` for active calls and, if retained in the
  diagnostic, endpoint/call associations. Implement counts with the registry
  read lock and direct map/counter reads; do not allocate slices.
- [x] Update the `callregistry.Registry` contract and its implementations or test
  doubles consistently if the count accessors belong on the interface.
- [x] Remove both eager `ActiveCalls()` calls from
  `CallTracker.GetCallIDForRTPPacket`.
- [x] Ensure successful destination and source lookups do no work proportional
  to active-call count and do not construct unused diagnostic fields.
- [x] Correct the lookup-failure diagnostic: do not label the same active-call
  count as both endpoint-map sizes. Remove misleading fields unless accurate,
  constant-time values are available.
- [x] Add a logger-level query that reflects the active handler and
  `logger.Disable()` state, or use the underlying handler's `Enabled` contract,
  so expensive debug fields are only computed when a debug event can be emitted.
- [x] Compute diagnostic counts only on the miss path and only when debug output
  is enabled. Keep miss counters and sampled diagnostic-buffer events working
  when normal logging is disabled.
- [x] Change `GetTrackedCallCount` to use the new constant-time count accessor.
- [x] Preserve the existing throttled RTP LRU touch behavior and exact endpoint
  lookup semantics.

## Phase 3: Add RTP regression coverage

- [x] Add tests proving logging-disabled hits and misses do not call
  `ActiveCalls()` or otherwise materialize the active-call collection.
- [x] Add tests for accurate debug diagnostic counts when debug logging is
  enabled and for no debug-field computation when logging is disabled.
- [x] Keep functional coverage for destination match, source match, miss,
  multiple calls sharing an IP, and throttled registry touches.
- [x] Add scaling benchmarks demonstrating that lookup time and allocations do
  not grow with active-call count. Require constant allocation behavior rather
  than zero allocations until endpoint formatting is separately optimized.
- [x] If endpoint formatting remains material in the new profile, replace the
  `fmt.Sprintf` constructions with a measured lower-allocation representation
  without changing IPv4/IPv6 endpoint-key compatibility.
- [x] Relabel the statistics panel to distinguish the instantaneous sampling
  policy from cumulative detail retention, for example `Current sampling`, and
  add/update rendering tests for the wording.

## Phase 4: Implement detector batch eviction with hysteresis

- [ ] Review and port the production-validated batch patch as the starting point
  for both `FlowTracker` and `DetectionCache`; keep the two implementations
  behaviorally consistent through a shared helper only if doing so remains
  clearer than duplication.
- [ ] When a capped map is full, evict a batch targeting 10% of the configured
  maximum, with a minimum batch of one and no possibility of exceeding the hard
  cap on the subsequent insertion.
- [ ] Preserve the existing victim semantics: `FlowTracker` orders by oldest
  `LastSeen`, while `DetectionCache` orders by earliest expiration.
- [ ] Reuse scratch storage only while protected by the owning lock, reset it so
  removed entries are not retained, and document the ownership invariant.
- [ ] Ensure batch selection does not perform one full scan per victim. Measure
  the chosen one-pass/selection, bounded-heap, or sort-based implementation at
  the 100,000-entry default before accepting it.
- [ ] Keep the initial cap warning, but replace the permanently silent
  `capWarned` condition with a rate-limited warning or pressure-episode state
  that becomes observable again after the map falls below the threshold.
- [ ] Avoid moving eviction outside the lock without an explicit versioning and
  revalidation design; correctness takes precedence over an unsafe reduction in
  lock duration.

## Phase 5: Fix detector synchronization and cleanup stalls

- [ ] Define and document the synchronization owner for mutable
  `FlowContext` fields, especially `LastSeen`, `Protocols`, and `Metadata`.
- [ ] Route flow updates through a tracker-owned update method or another clear
  synchronization boundary so cleanup/eviction reads cannot race with detector
  writes after `GetOrCreate` returns.
- [ ] Audit all `FlowContext` readers and writers and add concurrent tests that
  exercise lookup, protocol updates, eviction, expiration, deletion, and clear.
- [ ] Replace the once-per-minute monolithic expiry scan under the exclusive lock
  with bounded incremental cleanup, sharded cleanup, or time-bucketed expiry.
  Preserve TTL behavior while bounding any single lock hold.
- [ ] Keep lifecycle shutdown safe and idempotent while changing cleanup state;
  verify no cleanup goroutine or timer survives `Close`.
- [ ] Run targeted detector tests under the race detector and resolve all races
  attributable to these paths before completion.

## Phase 6: Detector tests, benchmarks, and observability

- [ ] Add table-driven eviction tests for caps of 1, 2, values below 10, and
  representative larger limits; cover disabled caps and existing-key updates.
- [ ] Test that each eviction leaves the expected hysteresis, removes the oldest
  eligible entries, respects the hard cap, and permits subsequent insertions.
- [ ] Add sustained-at-cap benchmarks for both `FlowTracker` and
  `DetectionCache` at 1,000, 10,000, and 100,000 entries.
- [ ] Add a contention benchmark with concurrent detector workers and report
  batch-event latency in addition to average throughput.
- [ ] Define measurable acceptance criteria: steady-state insertion must no
  longer scale linearly with cap, and the 100,000-entry batch pause must remain
  below the packet-buffer latency budget on supported production hardware.
- [ ] Expose current flow/cache entries, total evictions, expired removals,
  pressure episodes, and eviction duration/batch size through the existing
  processor/tap heartbeat or metrics path.
- [ ] Keep metrics updates constant-time and non-blocking on packet-processing
  paths; document counter reset and aggregation semantics.
- [ ] Update operator documentation to explain cap pressure, the throughput vs.
  retention tradeoff of lowering `detector.max_flows`, and the new telemetry.

## Phase 7: Define and enforce per-call PCAP finalization

- [ ] Document the per-call writer state machine, including live, finalizing,
  finalized/tombstoned, optional late-packet output, and manager shutdown states.
- [ ] Move completed Call-ID ownership into `PcapWriterManager` so the component
  that admits writer creation also enforces terminal state.
- [ ] Add a bounded tombstone set with configurable or internally documented TTL
  and cardinality limits; use the existing one-hour closed-call retention as a
  compatibility baseline unless production evidence supports another value.
- [ ] Make removal from the live map and installation of the tombstone one atomic
  manager-locked transition, then release the manager lock before file syncing,
  closing, endpoint cleanup, logging, or invoking external callbacks.
- [ ] Make `GetOrCreateWriter` return a typed, non-fatal finalized-call result for
  tombstoned Call-IDs and emit a rate-limited warning plus a suppressed-late-
  packet counter. Do not represent expected late-packet suppression as a generic
  file creation error.
- [ ] Decide and document the policy after tombstone expiry. If Call-ID reuse is
  admitted, filename generation must still prevent collision with any prior
  finalized artifact.
- [ ] Remove modification-time heuristics as the authority for logical writer
  continuation. Appending is allowed only when manager-owned live lifecycle
  state proves that the file belongs to the same unfinished call generation.
- [ ] Open newly created per-call artifacts without destructive replacement of
  an existing non-empty path. On collision, fail safely or allocate a unique
  generation/part name; never fall back to `O_TRUNC` for an ambiguous artifact.
- [ ] If late-packet retention is required, write to a distinct `.late` or
  generation-suffixed PCAP, give it a valid standalone header, and ensure it
  cannot trigger the normal `OnCallComplete` hook again.

## Phase 8: Unify closure paths and remove writer lifecycle races

- [ ] Route explicit BYE/terminal-state completion, `SweepIdle`, and
  `MaxWriters` eviction through one manager finalization API with an explicit
  close reason.
- [ ] Ensure every terminal path dissociates RTP endpoints before output
  finalization, records the completed Call-ID, and invokes the completion hook
  at most once.
- [ ] Remove the current idle-sweep bypass of
  `CallCompletionMonitor.closeCallPcap`; idle finalization must update closed
  state and call `VoIPPortCleaner.CleanupCallPorts` just like explicit closure.
- [ ] Decide whether capacity eviction represents call completion or resource
  pressure. Preserve the capture under a collision-proof partial/final artifact
  and expose the reason rather than silently presenting an active call as a
  normal protocol-complete call.
- [ ] Eliminate the lookup-then-write race in which a manager returns a writer
  that can be closed before `WriteSIPPacket` or `WriteRTPPacket`. Keep the write
  under a manager lifecycle lease or expose manager-owned packet-write methods.
- [ ] Make `CallPcapWriter.Close` and manager finalization idempotent and safe for
  concurrent calls; stopping the sync goroutine or closing a channel twice must
  not panic.
- [ ] Clear or terminally guard PCAP writer/file fields after close so a retained
  pointer cannot attempt to write through a `pcapgo.Writer` backed by a closed
  file.
- [ ] Do not invoke `OnFileClose`, `OnCallComplete`, command hooks, or other
  externally supplied callbacks while holding manager or writer locks. Preserve
  deterministic callback ordering and define how callback failures are logged.
- [ ] Keep shutdown distinct from call completion: close and flush all live
  writers without accidentally firing completion hooks unless existing operator
  semantics explicitly require it.
- [ ] Consolidate the monitor's `closedCalls` state with manager tombstones or
  define a single authoritative relationship so the two TTL sets cannot drift.

## Phase 9: Per-call PCAP regression and integration coverage

- [ ] Reproduce the incident with a filename pattern lacking `{timestamp}`:
  write a multi-packet call, finalize it, inject a late packet for the same
  Call-ID, and assert the original file's size, bytes, and hash are unchanged.
- [ ] Assert the normal completion hook fires exactly once across explicit,
  idle, capacity, duplicate-close, and late-packet paths.
- [ ] Test idle finalization end to end: it records a tombstone, removes endpoint
  mappings, suppresses resurrection, and reports the correct close reason.
- [ ] Test endpoint reuse by a genuinely new call after an old call completes;
  traffic must resolve only to the new Call-ID and must not mutate old files.
- [ ] Cover tombstone expiration and capacity pruning, including legitimate
  Call-ID reuse after expiry and collision-safe artifact naming.
- [ ] Test restart/crash recovery with pre-existing empty, valid, partial, and
  finalized PCAP paths. No startup or first-packet path may silently truncate a
  non-empty file.
- [ ] Add concurrent write/finalize/get-or-create/idle-sweep tests and run them
  under the race detector, including a late packet arriving during finalization.
- [ ] Add blocking and re-entrant callback tests proving callbacks execute
  without manager/writer locks and cannot deadlock packet writing or shutdown.
- [ ] Inject sync, close, create/collision, endpoint-cleanup, and callback
  failures; assert errors retain call/file context and terminal bookkeeping
  remains internally consistent without reopening finalized output.
- [ ] Verify rotated SIP and RTP files preserve valid PCAP headers and callback
  ordering under the new generation and collision policy.
- [ ] Add an end-to-end filtered VoIP test covering matched INVITE, in-dialog BYE
  without the originally matched identity, prompt endpoint cleanup, one writer
  finalization, and exactly one command hook.
- [ ] Expose active writers, finalizations by reason, suppressed late packets,
  tombstone occupancy/eviction, filename collisions, and callback failures
  through the existing heartbeat or metrics path.
- [ ] Benchmark tombstone lookup/pruning and concurrent manager-owned writes;
  require constant-time steady-state admission and bounded finalization pauses.

## Completion criteria

- [ ] RTP lookup hit cost is independent of active-call count, with no active-call
  slice construction and no eagerly computed disabled-log diagnostics.
- [ ] Flow and cache insertion at cap no longer performs a full-map scan for
  every new entry, and batch pauses meet the documented latency threshold.
- [ ] Detector mutable flow state has a race-free ownership model and cleanup no
  longer monopolizes the exclusive lock for an unbounded full scan.
- [ ] Operators can observe current occupancy, eviction activity, expiration,
  and eviction latency without enabling debug logs.
- [ ] Every per-call PCAP finalization route is idempotent and installs bounded
  terminal state before accepting another packet for that Call-ID.
- [ ] Finalized artifacts are immutable, command hooks fire at most once, file
  collisions are non-destructive, and late packets follow an explicit policy.
- [ ] Idle and capacity-driven writer reclamation cannot leave stale endpoint
  associations or bypass completed-call suppression.
- [ ] Unit, race, tagged integration, benchmark, profile, and live-soak evidence
  demonstrate that the fixes preserve detection and call-correlation behavior.
